## Model in one paragraph
Everything priced is a **price book (publication)** with a monotonically increasing `version`: a book carries price rules, markdowns, promotion **rules**, coupons and **campaigns**. A hub write = `POST /api/v1/commercial/publications` (draft) + `POST .../{id}/publish`. A campaign is the envelope (window, budget, stores, poster); a promotion is a rule inside a book; **pause/end of a promotion republish the rule as a new book**, pause/end of a **campaign** is `PATCH /commercial/campaigns/{id}` (dispatches at once). Nothing is edited in place: Change = next version under the same id, Duplicate = new id. **No approval step.** **No segment-targeted promotions** (rule scope has only EVERYONE/MEMBERS). Promotion stores come from the campaign (`site_ids`), a rule's own `site_ids` has no control on the form.

The shop sees every published promotion: `POST store-01 /api/v1/store/quote` with an empty basket lists each rule as `{applied, reason, benefit_minor}` — the tests use it to prove that a hub action reached the till.

## Promotions (`/commercial/promotions`)
- Header: `Sync usage to stores` (POST `/commercial/usage/publish`; "Sent automatically every 5 minutes"), banner "N promotion(s) has/have reached the budget. Sync usage to stores." (usage ≥ budget), "Published, but no store is registered to receive it."
- Phase tabs (server-counted, with counts): `All N · Live N · Paused N · Scheduled N · Ended N`. Phase = status + window: EXPIRED→Ended; window closed→Ended; not ACTIVE→Paused; start in future→Scheduled. Empty tab (no search): "No <phase> promotions."; empty search: "No matches."; none at all: "No promotions."; from a campaign with none: "No promotions in <campaign>." + New promotion.
- Row: Promotion · Status (switch `Pause <name>` / `Resume <name>` for Live/Paused only + pill) · Applies to ("N SKUs", "Article <code>", "Division X", "Tagged X", "The whole basket", + " · members only") · Benefit ("20% off", "Rp 50.000 off the basket", "Rp 150.000 each", "Buy 2, get 1 at 100% off", "1 point per Rp 10.000") · Stores ("1 / 1", "· N pending", "· N failed") · Usage ("Never used" / "N uses · Rp x") · Period.
- Rail filters: Stores, Used (number bands; URL `reached`, `usage`). Chip `Campaign: <name>` with × `Show every campaign` (`?campaign=`).
- Pause → dialog "Pause <name>?" body "Stores stop giving this discount. You can resume it any time." [Cancel] [Pause]; Resume has no question. Receipt dialogs: "Paused — sent to N store(s)", "Resumed — sent to …", "Ended — sent to …", "Published — sent to …".
- Sheet (`?rule=`): tabs Details (Offer: Benefit, Applies to, Period, Campaign, Last changed · Rules: Shoppers, Items already on sale, Other offers, Minimum items/basket, Code, Budget, Transactions limit, Per shopper, Priority · Performance: Spent/Budget used, Transactions, "Split between stores" switch) · Stores (N) (Store/Status/When: In service · Sent, not applied · Failed · No report) · Activity. Head: `Change`, `Duplicate`, `End now` (only while Live/Paused/Scheduled; confirm "End <name> now?" / "Stores stop giving this discount for good."). Badge "Needs code X".
- **New / Change / Duplicate form** (title New promotion / Change promotion / Duplicate promotion; sheet, `?new-rule=true`):
  - Promotion: `Name (required)` (problem "Give the promotion a name."; **once blurred the problem text becomes part of the accessible name, and the extra line shifts everything below — fill the name first**); Campaign combobox "The campaign this offer belongs to" (picking restates the campaign verbatim: poster + stores kept).
  - Discount radios: Percent off · Amount off · Fixed price · Buy X get Y · Points. Percent: textbox "Per cent off" + quick 10/20/30/50/70%. Amount: textbox "The figure this promotion applies" (labels "Amount Off The Basket" / "Price Each" / "Spend Per Point"). Buy X get Y: "Units to buy in each bundle" (2), "Rewarded units in each bundle" (1), "Discount on rewarded units" (100%, quick 25/50/75/100). Points: radios "Best rate only / Add the extra / Multiply" under "With a better points offer". Problem "Set the discount."; BXGY: "At least one." / "Between 1% and 100%."
  - Applies to radios: Articles (combobox "The articles this promotion applies to", type ≥2 chars, option, **Escape closes the list**) · SKUs ("The SKUs this promotion applies to") · Divisions · Tags (toggle buttons from the vocabulary) · Whole basket. Problem "Choose what it applies to."
  - Schedule: Day pickers "The day this promotion starts" / "The last day this promotion runs" (presets Today/Tomorrow/In a week; In a week/In a month; textbox "Type The day this promotion starts" + Enter). Problem "The end date has to be after the start."
  - Rules radios: Everyone/Members only · Not on sale items/Sale items too · Blocks every other offer/Blocks offers on its items.
  - `Limits` fold (shows "N set"): "Coupon code" (upper-cased), "Least matching units", "Least value of the matching lines", "Budget", "Most transactions", "Most transactions for one shopper", "Priority".
  - Summary + till preview ("1 × Sample item Rp 199.000 … Total · sample"; "Under the Rp X minimum."; "Points earned N"). Footer: one-line offer, or the problem after a failed Publish; `Publish` / "Publishing…". Change keeps id, coupon, spent/used, and "Stays paused". Duplicate starts without the coupon code.
  - Server refusals show in a red banner in the sheet. Close with × / Escape discards silently.
- API: `GET /commercial/rules?limit&q&phases&campaigns&sort&desc&stores_min…`, `GET /commercial/coupons`, `GET /commercial/usage`, `GET /commercial/activation` (fleet = shops that have reported; the rig has **one**: store-01), `POST /commercial/publications`(+`/publish`), `POST /commercial/usage/publish`.

## Campaigns (`/commercial/campaigns`)
- Header: textbox (unnamed) + `New campaign`. Empty: "No campaigns." + New campaign; no match: "No campaign matches that search." / "No campaign matches those filters."
- Columns: Campaign · Status (switch `Pause/Resume <name>` for Live/Paused; pills Draft/Scheduled/Ended/Cancelled; "Starts <day>" for a future ACTIVE) · Objective ("Not stated" when no intent) · Target ("≥ Rp 5.000.000 promo sales") · Offers · Budget Used (meter, "Rp x / Rp y" or "· no limit") · Stores ("1 / 1") · Runs ("09 Oct 2026 → 24 Oct 2026" / "always → open"). Rail filters Status (`live:isAnyOf:ACTIVE|PAUSED|SCHEDULED|EXPIRED|DRAFT|CANCELLED`), Objective (`objective:isAnyOf|isEmpty|isNotEmpty`), Offers (`rules:`), Stores (`reached:`), Ends (`window:`).
- Pause dialog "Pause <name>?" / "Offers inside it stop at the tills."; receipts "Paused — sent to N store(s)", "Live again — sent to …", "Ended — sent to …", "Published — sent to …" (or "— no store to send it to yet").
- Sheet (`?campaign=`): head Change · Duplicate · Pause/Resume · End now (confirm "End <name> now?" "Every offer inside it stops at the tills for good." → status CANCELLED). Details: **Next steps** (Add an offer → promotions form pre-set; Set a goal; Plan activities · optional; Set a budget · optional; vanishes once offer+goal exist) · Campaign (Status, Period, Stores, Budget used, Transactions, Split between stores) · Offers · Goal (Change; form: Objective/Metric/Measured as selects, `Target`, "Compared with"; problem "Set a target.", "A percentage can't pass 100%.") · Results · Activities (Add: Kind, Name*, Reference*, Cost, Starts, Ends) · Reach (Declare) · Limits (Check now, Add) · **Poster** (Headline, Image URL, Terms, `Submit` → "Sent to stores.", no new book, disabled until changed). Tabs Stores (N) · Activity.
- Form (New / Change / Duplicate campaign): Name (required) "Give it a name."; Status select Draft/Scheduled/Paused/Live (Ended/Cancelled never offered); Starts (today) / Ends day pickers ("Ends before it starts."); Budget "Budget for the whole window" ("Whole rupiah only."); "Most transactions"; **Stores tiles**: `Everywhere` + one button per shop in the fleet (rig: only `rig store-01`; "all 16 stores" cannot be exercised, the stores come from `/commercial/activation`); `Poster` fold (Headline, Terms, Image URL); Summary; Publish. Id = slug + 4 random chars; Change keeps id/status ("Stays paused").
- API: `GET /commercial/campaigns`, `PATCH /commercial/campaigns/{id}` (status + poster, dispatches), `PUT/GET /commercial/campaigns/{id}/intent`, `/plan`, `/outcome`, `/target`, `/guardrail-check`.

## Vouchers (`/commercial/vouchers`)
- Figures strip (Outstanding · Issued · Spent · Cancelled · Expired, from the ledger of the whole book), tabs `All · Live · Spent · Cancelled`, "N vouchers", textbox, `New voucher`, `Coupons` (reader sheet: Code / Unlocks / Member / Valid / Max Uses; "No coupons."). Columns Voucher (code + Gift card/Refund/Goodwill) · Member ("Anyone") · Face Value · Left on It · Status (+ "· Expired") · Issued. Rail filters Face value, Left on it, Status (Live/Expired/Spent/Cancelled), Issued. Empty: "No vouchers." / "No vouchers match." + Clear filters.
- New voucher sheet: kind radios Gift card/Refund/Goodwill; `Value (required)` ("Enter a value." on blur; Submit disabled while ≤ 0); `Expires` day; Member (optional) combobox over the directory; `Code` (blank = minted); `Note`; `Submit`. Success opens the voucher sheet; a refusal shows a red banner.
- Voucher sheet (`?voucher=`): title "<Kind> · Rp balance"; head `Spend` (toggle) and `Cancel voucher` while Live. Spend form: `Amount (required)` ("Only Rp X is left."), Sale ID, Note, button "Spend Rp N" (disabled ≤ 0 or > balance). Cancel: dialog "Cancel <code>?" "Rp X left on it can't be spent." with `Reason` (≥ 4 chars: "Give a reason (at least 4 characters).") [Keep] [Cancel voucher]. Tabs Details · Ledger (N) (+Rp / −Rp, Left) · Activity.
- API: `GET/POST /commercial/vouchers`, `GET /commercial/vouchers/{code}`, `POST …/redeem {amount_minor}`, `POST …/void {reason}`; list returns `ledger`.

## Members / Segments
- `/members`: segment tabs Everyone · New · Active · Lapsing · Lapsed · Never bought · Stopped, textbox, `Filter`; "N found · M enrolled"; columns Member/Segment/Spend/Transactions/Avg Transaction/Units/UPT/Points/Points Spent/Last Purchase; sheet (`?member=<card>`): Card, Joined, First bought, Last purchase, Spend, Transactions, Avg transaction, Units, UPT, Points held/earned/spent, Saved by promotions, On voucher, App, `Issue a pairing code` ("Read these out to <card>", 6 digits, "Good for m:ss"), "Their transactions". Enrolment is a till/counter write (`POST /members`, cashier), no hub button.
- `/members/segments`: KPIs Enrolled · Buying now · Member spend · Active within 90 days · Lapsed after 180 days · Not enrolled; six built-in segment cards (each `Open the list`), saved-segment cards (name, "N% of members", conditions sentence, purpose, `Edit`, `Retire segment`, `v1`); `New segment` sheet: `What it is called (required)`, `Why it exists`, radios "Every condition holds"/"Any one of them holds", `Add a condition` (column select, operator select, value), live preview "N of M members", `Cancel`/`Submit` (disabled with the problem line: "A segment needs a name — …", "Add at least one condition. …", "One of the conditions is not finished."). Edit title "Edit segment" (new version); Retire dialog "Retire <name>?".
- **Points scheme** = the promotion `rule-poin-member` ("Poin member: 1 poin per Rp 10.000", EARN_POINTS SPEND_RATE Rp 10.000, members only). There is no separate scheme editor: Points is an effect on the promotion form.
