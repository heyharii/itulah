Kelima Nordic variant berbeda secara visual, tetapi membaca dan menulis backend yang sama.

UI actionEndpointRequired contractNordic interaction rule
Supplier listGET /api/v1/suppliers?status=…Loaded array; no server search/paginationSearch labeled as filter over loaded rows
Create / edit SupplierPOST / PATCHIdempotency-Key; strong If-Match for updateQuiet form, explicit stale-version recovery
Supplier ItemsGET /api/v1/suppliers/{id}/itemsCurrent IDR price, optional Article linkAlways label price as current, never stock/terms
Status changePOST …/activate | deactivateIf-Match + Idempotency-Key; no DELETEUse calm warning confirmation, never trash icon
Direct catalog POPOST /api/v1/purchase-orders/catalogCanonical IDs, positive qty, exact DC, keyCTA says Create & issue; local preview is clearly non-authoritative
Recommendation: Fjord as the product shell; Aurora as the wide PO composer; Harbor density for advanced tables.Standalone visual prototype · no API calls · backend-informed
