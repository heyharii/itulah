## Bayar — `Payment` in `till.tsx`, `pay-d.css`

Rows (pay look E): Tunai · EDC (one or more) · Voucher · Diskon karyawan · Poin (only with a member).

P1. **Amount column:** empty until the row is verified, with no box and no lock. Tunai is always open.

P2. **EDC row "Satu per satu"** (`edcMid`, `edcAsk`, `edcSetBank`, `edcSetKind`, `edcSetCard`, `edcUndo`, `edcFill`, `edcMore`, `edcPlus`, `edcDigit`):
    - **Order:** Mesin, then Jenis (Debit / Kredit / QRIS when that bank has QR), then Kartu (bank of the machine = On us `Y`, Bank lain = Off us `T`; not asked for QRIS).
    - **Nothing is preselected.**
    - **Answered lines:** each shrinks to the chip picked (solid accent) with ×. Clicking it takes that answer back with every later one.
    - **Key chips beside the answers** (focused row only): `← →` another machine, `D K Q` another kind, `Y T` the card.
      - Pressing the key of the current answer does nothing.
    - **The line being asked:** amber label; its options as chips with their key (machines `1 2 3`).
    - **Keys:** digits 1–n pick the machine only while Mesin is asked. Backspace on an empty amount takes back the last answer.
    - **Amount:** once all answers are in, it fills with the rest (auto, typing replaces it).
    - **Several EDCs:**
      - A finished, focused EDC row shows "Tambah EDC [+]".
      - `+` or `=` from any row jumps to an EDC still unanswered, or adds "EDC 2" under the last EDC.
      - An added EDC row left empty disappears when the focus leaves it.
    - **Pembayaran diterima** is refused while an EDC row with money has an open question; the question turns red.
    - **Machines:** come from the store's EDC setting (session edc-per-store adds an `api` function; until it exists use today's list).

P3. **Voucher:**
    - The code field sits in the amount column, uppercase.
    - A valid code shows "Komplimen · CP-QA19-X04M · saldo 50.000 ×" in the middle. The amount is grey, not typeable, = min(balance, rest), and fades in.
    - × or Backspace/Delete on the row removes the voucher, and the cursor goes back to the code field.
    - An unknown 12-character code is marked red with the note "Voucher <code> tidak dikenal".

P4. **Poin:**
    - The middle shows "12.500 poin = Rp 125.000".
    - The amount column holds the field "Kode dari app" (6 digits) until the code is right. It is skipped when the member was found by scanning the card.
    - The right code turns the field into the amount input, which fades in. A wrong code turns red with "Kode salah · minta pelanggan buka app member".
    - F1 "Semua poin". Capped at points × Rp 10 and at the rest.

P5. **Reveal:** an amount that opens after a code or finger fades in once from `blur(4px) scale(.97)`, 220 ms ease-out; opacity only under reduced motion. EDC answers do not animate.

P6. **Codes and arrows:** arrowing onto Voucher or Poin puts the cursor in its code field. ↑/↓ inside a code field move to the next row.

P7. **Keypad:** hidden by default. The button reads "Tampilkan keypad [F8]" / "Sembunyikan keypad [F8]" and the choice is remembered per till (`localStorage` `pos.pad`).

P8. **Unchanged:** Tunda (red, 40 px) beside "Pembayaran diterima", member question first, "Transaksi selesai".

## Backend (edge + cloud)

B1. **Tie a member to an earlier sale.** `POST /api/v1/store/sales/member` with `{ receipt_no, member_id }` (till auth).
    - Reply `200 { sale_id, receipt_no, member_id, member_name, points_earned }`.
    - **Refusals:** 404 "Struk <no> tidak ada"; 409 "<no> sudah atas nama <name>"; 409 "<no> sudah di-void" / "<no> sudah ditukar".
    - **What it does:** records the member on the node's sale and gets it to the cloud, so the member earns that sale's points exactly as if the member had been on it at the time (same earning rule; idempotent per sale).

B2. **Setor modal.** A cash movement kind for returning the float, e.g. `FLOAT_RETURN` (or DROP plus a flag; the agent picks and documents it), with the supervisor as receiver.
    - It is allowed while the shift is open and does not close it.
    - Its slip is numbered `SM-0001` and has the same shape as the TM/ST slips: `{ slip_no, amount_minor, given_by_name, received_by_name, at }`, giver = the cashier.
    - The shift report gains `float_returned_minor` and `float_returned_to` (name, or null), so the till and the closing paper show it.
    - Migrations if needed: postgres `0992_…`, sqlite `0089_…`. Other sessions own 0989–0991 / 0086–0088.
