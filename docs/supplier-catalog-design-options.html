Itulah · Supplier Catalog · Design exploration

Lima taste. Satu kontrak operasional.

Studi UI table-first untuk Supplier → Supplier Items → Purchase Order. Kelima opsi memakai data dan aksi yang benar-benar tersedia di backend, sehingga perbedaannya murni pada taste, density, hierarchy, dan ritme kerja.

Basis riset: Cloud Rust/Axum, PostgreSQL Supplier Catalog, role SUPERVISOR, idempotency, ETag, IDR-only price, serta exact-target DC command. File ini adalah prototype visual—tidak melakukan request API.

UI → backend contract

Checklist implementasi bersama untuk kelima taste. Core mutation sudah tersedia; sumber dropdown registered DC tetap perlu dihubungkan ke fleet/config surface yang dapat diakses buyer.

UI intentEndpointHeaders / inputAuthoritative behaviorDesign implication
Load Supplier directoryGET /api/v1/suppliers?status=…Status optionalBare array; active first, then nameSearch adalah client-side atas loaded rows; jangan tampilkan pagination palsu
Create SupplierPOST /api/v1/suppliersIdempotency-KeyCode/name required; contact optional; returns ETagForm pendek, tanpa bank/payment/terms
Edit SupplierPATCH /api/v1/suppliers/{id}If-Match “version” + Idempotency-KeyStale version → 409; null clears optional fieldSimpan ETag dan tampilkan refresh/reconcile conflict
Load Supplier ItemsGET /api/v1/suppliers/{id}/itemsStatus optionalCurrent price, IDR, optional Article linkHarga diberi label “current”; bukan terms/history
Activate / deactivatePOST …/{id}/activate | deactivateIf-Match + Idempotency-KeyVersion increments; no delete or cascadeGunakan warning confirmation, jangan ikon trash
Create direct POPOST /api/v1/purchase-orders/catalogSupplier/item UUID, qty, date, DC, keyServer snapshots values and immediately issues to one DCCTA harus “Create & issue PO”; preview total hanya lokal
Recommendation: mulai dari Option 01 untuk integrasi tercepat; pinjam PO composer Option 05 sebagai wide dialog/page.Standalone prototype · no API calls · based on backend as of 31 Aug 2026
